# Витрина на GitHub Pages

Ветка `pages` публикует статическую копию витрины на
`https://<логин>.github.io/<репозиторий>/`. В `master` и в рабочую ветку ничего
не сливается: обновляется только `pages`.

Сделано по образцу `D:\Projects\GHEKATEX\app`: отдельный workflow поднимает
Laravel прямо в Actions, обходит его по списку адресов и публикует готовый HTML.

## Как это работает

1. **База.** В репозитории лежит срез боевой базы — `database/pages/dataset.sql.gz`
   (0,4 МБ): все разделы, бренды, меню, баннеры, секции главной и SEO-записи
   плюс 400 товаров с характеристиками, упаковками и медиафайлами.
   Workflow поднимает MySQL 8, прогоняет миграции и заливает срез поверх.
2. **Сборка.** `composer install`, `npm ci`, `npm run build`, затем
   `php artisan serve` на 127.0.0.1:8000.
3. **Экспорт.** `node tools/static-export.mjs` обходит адреса из
   `php artisan site:urls` и раскладывает ответы файлами `<путь>/index.html`.
   По дороге адрес приложения меняется на адрес публикации, корневые пути
   (`/build/`, `/v1/`, `/fonts/`) получают префикс подкаталога, а фотографии
   товаров уводятся на `https://radop.md` — снимков в репозитории нет.
4. **Публикация.** `actions/upload-pages-artifact` + `actions/deploy-pages`.

## Как обновить витрину

Запушить в ветку `pages` — workflow запустится сам:

```bash
git checkout pages
git merge storefront-tz-v9.1   # подтянуть свежие правки рабочей ветки
git push origin pages
```

Либо вручную: вкладка **Actions → GitHub Pages → Run workflow**, там же можно
задать, сколько карточек товаров выгружать (по умолчанию 400).

Перед первым запуском в настройках репозитория: **Settings → Pages → Source →
GitHub Actions**.

## Как обновить срез базы

Срез собирается на машине, где подключена боевая база:

```bash
php tools/make-pages-dataset.php --products=400 --out=database/pages/dataset.sql.gz
git add database/pages/dataset.sql.gz
git commit -m "Срез базы для Pages"
```

Товары берутся по нескольку из каждого раздела, поэтому разделы в демонстрации
не пустуют. Данные покупателей, заказы и пользователи в срез не попадают.

## Что на статике не работает

Корзина, оформление, вход, избранное и живой поиск требуют сервера: на Pages
они показывают интерфейс, но ничего не отправляют. В разметку страниц
добавляется флаг `window.__radopStatic = true` — по нему можно спрятать такие
элементы, если понадобится.

## Объём

78 страниц и ассеты занимают примерно 34 МБ, из них 11 МБ — наследные файлы
старой темы (`public/v1`), которые нужны шапке и подвалу. Полная выгрузка на
400 товаров — около 250 МБ при ограничении Pages в 1 ГБ. Если станет тесно,
уменьшите `--max-products` в запуске workflow.
