# SEO: как теги собираются при рендере и что чинить

Статус: P1 сделан (2026-10-03) — сборка head по слоям живёт в `app/Services/Seo/SeoHeadLayers.php`,
правила закреплены тестом `tests/Feature/Seo/SeoHeadLayersTest.php`. Осталось P2 и P3, см. ниже.
Связанные документы: `docs/seo-and-google-ads-plan.md`, `docs/seo/*` (редиректы nginx, Core Web Vitals, slug-миграция).

## Как это работает сейчас (слои, в порядке применения)

1. **Конфиг** `config/seotools.php` — заголовок без суффикса, общее описание, `canonical => null`
   (то есть `Url::full()` — в canonical попадает строка запроса), `robots = index,follow`,
   одна картинка по умолчанию `default.png`, OG-заголовок зашит строкой «Radop - Magazin online».
2. **Middleware** (глобальные, `app/Http/Kernel.php`):
   `CanonicalPathRedirect` — 301 для `/index.php`, `/ro/...`, слеша в конце;
   `SeoIndexingDirectives` — `noindex, follow` для приватных разделов и 16 видов параметров, плюс чистый `$seoCanonical`.
3. **Контроллеры** (artesaos/seotools) — title, description, картинка, `opengraph()->setUrl`, тип JSON-LD.
   Канонический адрес не задаёт **ни один** контроллер.
4. **`head/seo-directives.blade.php`** — подставляет `$seoCanonical`, запасной заголовок из `lang/*/seo.php`, директивы robots.
5. **`head/head.blade.php`** — генерация SEOMeta / OpenGraph / Twitter / JsonLd.
6. **`head/hreflang.blade.php`** — `ro-MD`, `ru-MD`, `x-default` через `App\Support\LocaleUrl`.
7. **`head/organization-schema.blade.php`** — JSON-LD `OnlineStore` на каждой странице.
8. **В теле страницы** — `components/breadcrumb-schema.blade.php` (`BreadcrumbList`), на товаре дополнительно
   `Product` + `Offer` из `app/Services/Seo/ProductSchemaOrgBuilder.php` (цена, наличие, рейтинг).
9. **Запасные значения** — `app/Services/Seo/SeoFallbackGenerator.php` (суффикс `| Radop.md`).
10. **Записи в БД** — таблица `seo_metas` (тип страницы + id + язык), читается репозиторием; `getStatic()` кеширует 2 часа.

## Что сделано (слой сборки head)

`App\Services\Seo\SeoHeadLayers` вызывается из `head/seo-directives.blade.php`
до `SEOMeta::generate()` и доводит то, что успели задать конфиг, запасной
генератор, запись `seo_metas` и сама страница:

- **Канонический адрес** строится из пути запроса плюс белый список параметров
  (сейчас только `page`). Раньше брался полный URL, и в canonical попадали
  сортировка, фильтры, utm и чужие метки.
- **Директивы индексации**: приватные разделы (корзина, оформление, избранное,
  поиск, вход, регистрация, кабинет) и любые параметры вне белого списка дают
  `noindex, follow`. Прежний middleware `SeoIndexingDirectives` удалён — правила
  живут в одном месте, список параметров больше не нужно поддерживать дважды.
- **Заголовок**: бренд добавляется ровно один раз (если его ещё нет в заголовке
  из базы), у страниц со второй и дальше — «— pagina N» / «— страница N».
  Страницы без записи в `seo_metas` и без своего заголовка получают его по
  разделу адреса, а не общее «Radop - Magazin online».
- **OG и Twitter**: `og:type` теперь из словаря (`website` / `product`), появились
  `og:site_name`, `og:locale` и `og:locale:alternate`, `og:url` равен каноническому
  адресу, добавлена карточка `summary_large_image`.

Проверено на наборе адресов: главная, раздел, `?page=2`, `?sort=`, `?filter[]`,
`?utm_source=`, неизвестный параметр, товар, бренд, каталог, поиск, корзина,
статика и `/ru/...`. Те же правила закреплены тестом.

## Что чинить (по приоритету)

### P1 — влияет на индексацию (сделано)

1. **Canonical с параметрами.** Ни одна страница не задаёт canonical явно, он берётся из полного URL,
   поэтому `?page=2`, `?sort=`, партнёрские и прочие неизвестные параметры попадают в canonical.
   Решение: один слой, который формирует canonical из маршрута и белого списка параметров;
   колонка `seo_metas.canonical` сейчас вообще не используется на витрине — подключить её как переопределение.
2. **Непоследовательное поведение без записи в `seo_metas`.** Товар, категория, бренд и главная
   подставляют запасные значения, а магазин, новинки, популярные, со скидкой, поиск, корзина, оформление,
   избранное, кабинет и статические страницы — ничего, и получают общий заголовок из `lang/*/seo.php`.
   Решение: единый резолвер «запись в БД → генератор запасных значений → общий дефолт» для всех типов страниц.
3. **Параметры вне белого списка.** Правила `noindex` покрывают `filter`, `sort`, utm и клик-id,
   но произвольные параметры оставляют страницу индексируемой с самоканоникалом.
   Решение: индексировать только известные параметры, остальное — `noindex, follow` плюс canonical без параметров.
4. **Заголовки.** Суффикс `| Radop.md` добавляет генератор запасных значений, и он же часто уже есть
   в заголовке из БД — на части страниц бренд повторяется дважды. Нужна одна точка, которая решает про суффикс.

### P2 — качество выдачи

### Структурированные данные (частично, 2026-10-03)

- Добавлен `WebSite` + `SearchAction` — поисковая строка сайта в выдаче.
- На списках (раздел, бренд, каталог, поиск) выводится `ItemList` со сквозной
  нумерацией: на второй странице позиции продолжаются с 25-й, `numberOfItems`
  равен общему числу товаров выборки.
- Осталось: `shippingDetails` и `hasMerchantReturnPolicy` в `Offer`, схема для
  страниц филиалов.

5. **OG и Twitter.** `og:type` заполнен несуществующими значениями (`category`, `articles`, `page`, `search`),
   `og:site_name` выключен, нет `og:locale` и `og:locale:alternate`, нет `twitter:card` — карточка в Twitter
   собирается по остаточному принципу. Картинка у листингов всегда одна общая.
6. **Структурированные данные.** Есть `OnlineStore`, `BreadcrumbList`, `Product` + `Offer`, `CollectionPage`, `WebPage`.
   Нет: `WebSite` + `SearchAction` (строка поиска в выдаче), `ItemList` на листингах,
   `shippingDetails` и `hasMerchantReturnPolicy` в `Offer` (Google Merchant это учитывает), схемы для страниц филиалов.
7. **Пагинация.** В `<head>` нет `rel=next/prev` (Google их игнорирует, это не критично),
   но заголовок, описание и H1 у всех страниц пагинации одинаковые — стоит добавлять «— страница N».
8. **H1.** Единого источника нет: на части страниц H1 живёт внутри партиала хлебных крошек,
   из-за чего возможны два H1 на странице. Свести к одному месту на макет.
9. **alt у картинок.** В унаследованных корзине и мини-корзине `alt` нет вовсе; нужен общий помощник
   «название товара + бренд», чтобы не дублировать логику по шаблонам.

### P3 — инфраструктура

10. **`seo_metas`** — нет уникального индекса по (тип, id, язык) и нет сброса кеша при сохранении записи в админке.
11. **robots.txt** — статический файл, язык `/ru` зашит, нет `sort=`/`perPage=`; стоит отдавать маршрутом,
    собирая правила из того же списка параметров, что и `SeoIndexingDirectives`.
12. **sitemap** — четыре файла плюс индекс, каждая страница выводится по разу на язык с полным набором alternates.
    Нет картинок (`image:image`) и `lastmod` у статических страниц.

### P3 — инфраструктура (сделано 2026-10-03)

- `seo_metas`: уникальный индекс по (тип, id, язык) — раньше на одну страницу
  могли завестись две записи, и какая попадёт в head решал порядок строк.
  Запись сбрасывает свой кеш при сохранении и удалении, правка в админке видна
  сразу, а не через два часа.
- Колонка `canonical` наконец работает: заполненный адрес перекрывает собранный
  из маршрута. Принимаем его только внутри того же языка — в базе есть русские
  записи с адресом без префикса `/ru`, и такой canonical увёл бы русскую
  страницу на румынскую.
- `robots.txt` отдаётся маршрутом и собирается из тех же списков, что и
  директивы индексации: закрытые разделы в обоих языках, шумные параметры
  (`sort`, `perPage`, `filter`, utm и клик-id), `page` остаётся открытым.
  Правила закреплены тестом `tests/Feature/Seo/RobotsTxtTest.php`.
  **Важно при выкате:** файл `public/robots.txt` удалён, иначе nginx отдавал бы
  его вместо маршрута.
- Карта сайта: у товаров появились фотографии (`image:image` — 13 248 из 14 122
  товаров со снимком), у статических страниц — дата изменения из `seo_metas`.

## Предлагаемая схема «слоёв»

Один конвейер вместо разрозненных мест: `SeoContext` (тип страницы, модель, язык, параметры запроса)
→ последовательность слоёв, каждый дополняет и может переопределить предыдущий:

```
defaults (конфиг) → fallback-генератор → запись seo_metas → контроллер/страница → директивы индексации
```

Выход — один объект, который шаблон `head` печатает целиком: title, description, canonical, robots,
OG + Twitter, hreflang, JSON-LD. Плюсы: одно место для правил, легко покрыть тестами
(«страница X при пустой БД даёт такой-то head»), и админка сможет переопределять любое поле.

## Как проверять

- Smoke-набор URL (главная, категория, подкатегория, товар, бренд, поиск, статическая, корзина, `?page=2`, `?sort=`, utm)
  — ожидаемые canonical / robots / title / JSON-LD. Сейчас это делается скриптом аудита, стоит закрепить тестом.
- Google Rich Results Test для `Product`, `BreadcrumbList`, `Organization`.
- После выката — Search Console: покрытие, дубли, «страница с параметрами».
