# Фото товаров: стандартизация и лишние перегенерации

Статус: план. Делается после правок по дизайну, вместе с блоком SEO.

## Как устроено сейчас

- Источник — папка `public/cert/`, файлы `<onec_id>_N.jpg` (сейчас около 12 тысяч).
  Путь задан в `config/media-files.php`.
- Всё проходит через `app/Services/Product/ProductImagesManager.php`:
  - `getProductImagesFiles()` ищет файлы по маске `<onec_id>*` — **маска без `_N`**,
    поэтому товару с кодом `100` попадают файлы товара `1000`;
  - `importProductImagesSafe()` копирует файл и кладёт в медиатеку, проверок на существование нет;
  - `updateProductImages()` сравнивает md5 исходника и уже загруженного и пропускает совпадающие —
    единственное место, которое сегодня хоть что-то не делает повторно.
- Запуск:
  1. **Импорт номенклатуры из 1С** (`POST /nomenclature`) → задания `ProductImportJsonJob`.
     Там на каждый товар: есть медиа → `updateProductImages()`, нет → `importProductImagesSafe()`.
     Это и есть место, где картинки перебираются при каждом импорте.
  2. Кнопка в админке «импорт изображений» → `ImportProductImagesJob` с `force = true`:
     чистит коллекцию и грузит заново **всегда**.
  3. Кнопка у товара «перегенерировать изображения» → то же самое для одного товара.
  4. Команды `products:import-images` (умеет пропускать товары с медиа без `--force`)
     и `products:optimize-images` (сломана: метод оптимизации ничего не возвращает, а результат используется как путь).
- Хранение: диск `media` = `storage/app/media`, путь `products/<onec_id>/`, конверсии в подпапке `conversions/`.
  Рядом лежат ~10 тысяч старых папок по id медиа — наследие до появления генератора путей.
- Конверсии на модели товара: `thumb` 150×150 и `medium` 264×264, обе в очереди. Адаптивных изображений нет.
- Инструменты: `spatie/image` 2.x (Glide), расширения gd и imagick в образе. `intervention/image` не установлен.

## Что это даёт сейчас

1. Каждый импорт номенклатуры перечитывает и пере-хеширует все файлы всех товаров — долго и бессмысленно.
2. Кнопки в админке очищают коллекцию и грузят заново, то есть **меняются URL картинок**
   (media id новый) — для поисковика это новые адреса и потерянные сигналы, в выдаче картинки выпадают.
3. Разный формат исходников (вертикальные, горизонтальные, с разными полями) ломает сетку карточек
   и даёт скачки вёрстки при загрузке.

## Что делаем

### 1. Пропуск уже загруженных картинок при импорте

- Починить маску в `getProductImagesFiles()`: `<onec_id>_[0-9]*` вместо `<onec_id>*`.
- В `ProductImportJsonJob` сравнивать количество исходников и количество медиа в коллекции:
  совпало — не трогаем товар вообще; не совпало — досыпаем недостающие, а не чистим коллекцию.
- Ту же проверку добавить в `ImportProductImagesJob` и `RegenerateProductImagesJob`,
  оставив обход только по явному `--force` (кнопка «перегенерировать» у товара).
- Логировать итог: сколько товаров пропущено, сколько обновлено.

### 2. Команда стандартизации изображений

`php artisan products:normalize-images` поверх `public/cert/` (до медиатеки, чтобы конверсии наследовали квадрат):

- вписывает изображение в квадрат заданного размера с сохранением пропорций и центрированием,
  добавляя белые поля (`spatie/image`: `fit(FIT_CONTAIN, $size, $size)` + белый фон);
- параметры: `--size=1000`, `--quality`, `--only=<onec_id>`, `--dry-run`, `--force`;
- по умолчанию пропускает файлы, которые уже квадратные нужного размера;
- пишет отчёт: обработано / пропущено / ошибки.

Python-скрипт не нужен: тот же результат даёт консольная команда на уже установленном `spatie/image`,
и она работает там же, где лежат файлы, без отдельного окружения.

### 3. Что это даёт SEO и интерфейсу

- URL картинок перестают меняться при каждом импорте — картинки держатся в индексе.
- Одинаковые пропорции: можно задать `width`/`height` в разметке и убрать скачки вёрстки (CLS).
- Меньше работы очереди на каждом импорте — быстрее обновление остатков и цен.

## Порядок работ

1. Починить маску и добавить пропуск по количеству (небольшая правка, сразу даёт эффект).
2. Команда нормализации + прогон на копии `public/cert` с `--dry-run`, выборочная проверка.
3. Прогон на боевых файлах в тихое время, затем выборочная перегенерация конверсий.
4. Проверить карточки, галерею товара, быстрый просмотр, экспорт и письма.
