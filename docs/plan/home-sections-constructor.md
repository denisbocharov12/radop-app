# Конструктор главной страницы

Статус: спецификация. Разработка — **после** правок по дизайну, отдельной веткой.

## Что сейчас

Порядок блоков главной зашит в шаблоне `resources/views/frontend/v1/pages/home/index.blade.php`:

1. скрытый `h1`;
2. слайдер баннеров (`banners`, таблица `banners` + `banner_settings` со скоростями);
3. три слайдера товаров подряд: новинки, топ продаж, со скидкой
   (выбор товаров — по `product_profiles.condition` = `new` / `popular` и по наличию `sale_price`);
4. слайдер брендов (`x-sf-brand-rail`).

Рядов с категориями на главной сегодня нет. Все выборки кешируются на 2 часа и сбрасываются
наблюдателями (`BannerObserver` — готовый образец для сброса кеша конструктора).

## Что делаем

Таблица секций + админка + динамический рендер. Порядок, видимость и настройки блоков редактируются,
а не правятся в коде.

### Данные

Таблица `home_sections`:

| поле | смысл |
|---|---|
| `id` | |
| `type` | `banners`, `product_rail`, `brands`, `seasonal`, (дальше `categories`, `promo`) |
| `title` | заголовок, переводимый (JSON, как `menu_items.title`) |
| `subtitle` | необязательная подпись, переводимая |
| `link_title`, `link` | ссылка «Смотреть все» |
| `is_active` | показывать |
| `order` | позиция |
| `settings` | JSON с настройками типа (см. ниже) |

Фон и прочие картинки — через медиатеку (collection `home_section_background`, `singleFile()`),
как уже сделано для `menu_items`.

Настройки по типам (`settings`):

- `product_rail`: `source` (`new` / `popular` / `sale` / `winter` / `category` / `manual`),
  `category_onec_id`, `product_ids[]`, `limit`, `autoplay`.
- `seasonal`: `overlay_color` (hex), `overlay_opacity` (0–100), `heading_style` (`light` / `dark`),
  плюс те же поля выбора товаров, что у `product_rail`.
- `banners` / `brands`: ничего, кроме общих полей.

### Секция «Сезонные новинки»

- **Фон** — картинка из медиатеки, `background-size: cover`, плюс слой-маска сплошным цветом
  с настраиваемой прозрачностью (цвет и прозрачность — в настройках секции).
- **Заголовок** — стандартный `.sf-section-title` темы, с вариантом для тёмного фона
  (белый текст + лёгкая тень), чтобы не изобретать отдельный стиль под каждую секцию.
- **Карточки товаров** — тот же `x-sf-product-card`. У `.sf-product` фон уже белый,
  понадобится только модификатор секции, чтобы маска не просвечивала и тень читалась на фоне.
- **Источник товаров** — по умолчанию условие `winter`, оно уже есть в перечислении условий
  и в карточке товара (бейдж), но у него нет ни страницы сортировки в админке, ни вывода на главной.
  Плюс вариант «вручную выбранные товары».

### Админка

Повторяем связку баннеров — она в проекте образцовая и уже знакома клиенту:

- маршруты `routes/v1/authorized/home_section/home_section.php` (префикс `home-sections`, имя `home-section.`),
  каждый маршрут с `app.permissions`;
- контроллер, FormRequest, DTO + маппер, менеджер, репозиторий, типизированные исключения —
  по той же схеме слоёв, что `BannerController` / `BannerManager` / `BannerRepository`;
- экраны: список, создание, редактирование, сортировка перетаскиванием
  (готовая пара `components/sortable-list` + `v2/partials/sortable-script`);
- права: имена маршрутов добавить в `PermissionSeeder` и в роли (`database/seeders/User/RolesWithPermissions/`),
  иначе `CheckPermissions` закроет доступ;
- пункт меню в `resources/views/v2/layouts/app.blade.php` (раздел «Контент», рядом с баннерами).

Админка остаётся на Blade + Alpine + Tailwind, как сейчас. Витринные стили сюда не тащим.

### Витрина

- `HomeSectionsRenderer` отдаёт отсортированный список активных секций с подгруженными связями;
- `home/index.blade.php` превращается в цикл по секциям, каждая — свой партиал,
  переиспользующий существующие компоненты (`sf-product-card`, `sf-brand-rail`, `.sf-rail`, `.sf-section-*`);
- кеш: как у баннеров (ключ с языком, сброс наблюдателем при сохранении секции);
- отсутствие секций = текущая раскладка по умолчанию (миграция создаёт четыре строки,
  повторяющие нынешнюю главную), чтобы выкат ничего не менял визуально.

## Порядок работ

1. Миграция + модель + сид с текущей раскладкой.
2. Рендер на витрине поверх сида (визуально ничего не меняется — это проверка).
3. Админка: список, создание, редактирование, сортировка, права.
4. Тип `seasonal` (фон, маска, заголовок, выбор товаров) и его стили в теме.
5. Проверка на десктопе и телефоне, документация для клиента в `docs/`.

## Риски и решения

- **Кеш**: забытый сброс даст «секция сохранена, но не видна» — наблюдатель и ручная кнопка сброса.
- **Переводы**: заголовки переводимые, пустой перевод подменяем языком по умолчанию.
- **Права**: без записи в сидерах разделы не откроются даже админу.
- **Производительность**: у каждой секции свой запрос; выборки кешируем и ограничиваем лимитом.
