# Заявки клиента (ТЗ)

Сюда кладём файлы с правками от клиента. Один файл — одна партия правок.

## Как класть

1. Имя файла: `YYYY-MM-DD-краткое-название.md` (например `2026-10-02-pravki-dizayn.md`).
   Подойдёт любой формат: markdown, текст, таблица, список со скриншотами.
   Скриншоты — в `docs/requests/assets/<имя-файла-без-расширения>/`.
2. Каждый пункт желательно с указанием страницы или блока: «главная → слайдер брендов», «карточка товара → цена».
3. Если пункт спорный или требует решения — помечаем `?` в начале строки, обсудим отдельно.

## Что происходит дальше

1. Разбираю файл на пункты и переношу в `docs/backlog.md` с номерами и статусами.
2. Для каждого пункта: правка → проверка в браузере на десктопе и телефоне → коммит со ссылкой на номер пункта.
3. Крупные блоки (новые модули) выносятся в отдельные документы со спецификацией и делаются после правок по дизайну.

## Статусы в backlog

- `todo` — принято в работу, ещё не начато
- `wip` — в работе
- `done` — сделано и проверено, с номером коммита
- `hold` — ждёт решения клиента (вопрос задан)
- `drop` — отклонено или потеряло смысл, с причиной
